# Diigolet 2

A self-contained [Diigo](https://www.diigo.com/) highlighter bookmarklet. The original Diigolet downloads its
engine from diigo.com, which most sites' Content Security Policy now forbids, so it silently dies on GitHub,
Wikipedia, HubSpot and many others. Diigolet 2 ships its whole engine inside the bookmark, paints highlights
through browser APIs that CSP does not police, and saves through channels no page policy governs. It runs on
desktop Chrome and Firefox and, because Android Chrome has no extensions, it is the way to highlight there.

Highlights are written in Diigo's own format (same `content` + `nth` anchoring, same MD5 ids), so they render in
Diigo's website, apps and official extension, and highlights made elsewhere render here.

## How it works

- **Entry.** Browsers exempt a bookmarklet's own code from the page CSP when it is launched from the address bar
  or a bookmark (Chromium `LocalFrame::LoadJavaScriptURL`, Firefox since 69). Only sub-resources are blocked, so
  the bundle loads nothing.
- **Painting.** CSS Custom Highlight API with a constructed stylesheet (CSSOM, not subject to `style-src`).
  Fallback: wrap text in `<em class="diigoHighlight …">` and colour via `element.style`.
- **Saving and loading.** A small helper page (`src/site/`) hosted on our own origin relays Diigo's JSONP API,
  reached first as a hidden iframe, then as a popup opened on a tap, and finally, when neither is possible, a
  fire-and-forget top-level navigation to diigo.com that works everywhere but cannot confirm.
- **Pairing.** The helper only obeys messages that carry the pairing token stored in that browser, so a hostile
  page embedding the helper cannot drive a visitor's Diigo account.

## Develop

```
npm install
npm test          # node:test unit tests (anchoring, ids, URLs)
npm run build     # dist/bookmarklet.js, docs/ (install + helper site), dist/bookmarklet.dev.js
npm run serve     # http://localhost:8765/ serves docs/
```

`docs/` is the built static site and is committed so GitHub Pages can serve it (Settings → Pages → Deploy from a
branch → `main`, folder `/docs`). `dist/bookmarklet.dev.js` is the bundle with a localhost helper and a fixed
pairing token baked in, for injecting into pages during automated testing; pair the local helper once by opening
`http://localhost:8765/#pair=devtoken0123456789abcdef01234567`.

## Layout

```
src/bookmarklet/   the engine: text model (Diigo anchoring), renderer, transport, UI, protocol, md5
src/site/          install page + helper relay sources
docs/              built site (generated by build.mjs, committed for GitHub Pages)
test/              unit tests
build.mjs          esbuild bundle + site assembly
```
